Try the local rehearsal

Requires Rust 1.91, Node 22+, Python 3, a C/C++ toolchain and CMake. The rehearsal uses simulated AI/SMS providers and real local SIP/browser media. It sends no live calls or texts.

tar -xzf parley-conference-kit.tar.gz
cd parley
bash scripts/setup-rvoip.sh
node scripts/verify-conference-dependencies.mjs
npm ci
npx playwright install chromium
PARLEY_BROWSER_CHANNEL=chromium bash scripts/run-conference-demo.sh rehearsal

The setup script creates a separate pinned Rvoip checkout beside Parley. On Linux, install Playwright system dependencies with npx playwright install --with-deps chromium. See the runbook for private credentials, live providers, recovery and scope.

One interface, three actions

An authenticated client addresses participants. The server resolves their private network endpoints and connectors. Keep mutating envelopes for an exact retry after a lost response.

const client = new UctpClient(url, participantToken);
await client.connect();

const update = client.command('message.send', cid, {
  msg_id: uniqueMessageId, to: [organizerId], delivery: 'sms',
  content_type: 'text/plain', body: 'Can we confirm the revised pickup?'
});
await client.request(update);

const invite = client.command('session.invite', cid, {
  to: organizerId, medium: 'voice', purpose: 'Confirm the pickup'
});
const accepted = await client.request(invite);

// After session.assistant_attached, from a browser user gesture:
await browserAudio.join(accepted.payload.session.sid);

These operations contact the provisioned participant in live mode. An accepted command is not proof of delivery or connected audio. The complete example and connector contract explain setup, event outcomes and browser negotiation.

Continue on another endpoint

Join the existing telephone call in your browser, then move your speaking connection to your provisioned phone through the same UCTP interface.

// From Jonathan’s authenticated browser, after joining:
const callback = await browserAudio.moveToPhone();
// Answer the callback and press 1 when prompted.
// Observe phone.speaking before retiring browser media.

The original remote call, Session and Conversation are retained. The browser remains connected until the callback is confirmed. This is an explicit endpoint move; automatic network-failure detection and gap-free audio are not claimed. The profile describes authorization, cancellation, exact retries and supported codecs.

What should we connect next?

Team messaging, email, radio, another SMS provider, or the network your community uses. These are contribution ideas; current examples cover SIP/PSTN, WebRTC, Telnyx SMS and Vapi.

  1. Open a Parley issue with your service, operation, capability limits and proposed local fixture.
  2. Share a runnable example and a redacted trace linking a request to its result and external outcome.
  3. For media adapters, contribute to Rvoip. For Conversation clients and the conference host, contribute to Parley.

Keep credentials, participant contacts and recordings private. Publish supported capabilities and distinguish acceptance, delivery and human replies. A reusable cross-provider messaging trait is still a contribution opportunity.
